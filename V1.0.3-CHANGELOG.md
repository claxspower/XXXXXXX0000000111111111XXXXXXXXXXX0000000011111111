# GsXFuscator V1.0.3 — Focused patch

## Scope

1. **Count-hook check (`+1` → `+2`).** When `debug.sethook` reports success, `debug.gethook` confirms the exact callback, a known arithmetic loop completes, restoring the hook succeeds **and** no count event fires, the startup check now adds 2 rather than 1. Since `Antidebug.THRESHOLD = 2`, this becomes a standalone deviation. **Trade-off:** host environments that lie about count-hook support can still trigger a false positive. Existing profiler hooks, missing APIs, and denied APIs skip the strong signal. This is not a guarantee against tampering or dumpers.
2. **Neutral output branding.** Protected Lua output now begins with `-- [Protected]` rather than the product/version heading. The anime ASCII artwork remains, but the overt `G s X`, `FUSCATOR`, `F U S C A T O R`, and `İS THE BEST` words have been blanked. The application UI still identifies its product, and transport markers may still reveal format to a knowledgeable analyst; this is an aesthetic/signature change, not a security boundary.
3. **Startup check caching audit.** The heavy probe block already runs **once per protected chunk** in V1.0.2, and the SEAL4 decoder already caches its hot-path byte/char/concat/reverse references. No additional `didInit` boolean was added because that would not speed up any actual repeated call. **Periodic VM integrity checks remain active** so late tampering is still observable.

**No VM or payload-format redesign.** SEAL4/SEAL2, VM9, `lua`/`luau`/`txt` drag-and-drop, both Sealed and Direct outputs, minified executable body, web bundle and optional coroutine wrapping are unchanged.

| Test | Observation |

**Not tested:** Native PUC Lua 5.1, actual Roblox/Luau clients, FiveM. No independent Clair/Luraph comparison was performed. The 1,000-line runtime is not a decode-only benchmark. Recompilation of existing protected files is required.

## Security boundaries

The self-hook test can distinguish particular inconsistent debug implementations, not detect every debugger or prevent runtime memory inspection. Hiding the banner does not hide the generator's identity from determined analysts. No cryptographic confidentiality is claimed for generated code.
