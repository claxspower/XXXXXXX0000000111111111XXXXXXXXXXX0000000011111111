# GsXFuscator V1.0.1 — Luau marker bypass hotfix

## Confirmed bug

V1.0 generated a Roblox marker from `_VERSION=="Luau"` alone and then used
that marker to reset the anti-debug score and skip parts of its runtime audit.
The marker did not disable SEAL4 payload checks or the independent VM opcode
and handler integrity checks. Claims that *all* protections were bypassed are
not supported by the source.

## Fix

- [V1.0.1] Platform detection now checks Luau, `typeof`, `game` and `workspace`
  instance types and class names together. A hostile host can still spoof these.
- [V1.0.1] Crucially, the platform marker **no longer suppresses** anti-debug
  results, late checks or VM primitive snapshots. A spoofed environment cannot
  turn off those checks merely by setting `_VERSION` or `typeof`.
- [V1.0.1] `runtime verification failed` replaces the branded integrity error.
  No fabricated syntax errors or random Lua exceptions are emitted.
- The previous nonintrusive sethook self-test stays advisory. Making a single
  `fired==0` observation a hard failure risks false positives on Roblox,
  profilers and constrained runtimes. An existing hook is not overwritten.
- Transient SEAL4 pool references were already released after decode. We do
  not force `collectgarbage` or nil active VM execution tables: those actions
  do not prevent host memory capture and can break legitimate code.
- `--coroutine-wrap` remains opt-in, as wrapping a program changes yield and
  `coroutine.running()` semantics; it cannot prevent a hostile host from
  dumping code.

## Limits

A host controlling Lua globals and native runtime can spoof any client-side
fingerprint or trace the VM. Payload-integrity checks are not cryptographic
signatures. Native Roblox/Luau and FiveM compatibility requires end-to-end
host tests; a 5.4 Lua harness is not a substitute.
