# GsXFuscator V1.0.2 — pooled metadata & decoder performance

## Changes

- **Unified lookup pool:** SEAL4 already pooled API references, encoded API field names and payload fragments in V1.0.1. V1.0.2 also places the fragment-order list and transport alphabet in that same seeded, sparse-index pool instead of top-level array literals. This increases uniformity, not cryptographic secrecy.
- **Hot-path function caching:** SEAL4 now resolves `string.byte`, `string.char`, `string.reverse` and `table.concat` through the existing `kb` helper **once** before iterating over payload bytes. Previous code performed a pooled member lookup via `kb` each time. Functions are checked for correct type before use.
- **Safe `sethook` handling:** Existing startup hook test is retained as an advisory signal, not escalated from `+1` to `+2`. `fired > 0` is the expected result of a working count hook; forcing errors on the number of firings causes profiler and host false positives. Existing hooks are left untouched.
- **Startup check caching:** Heavy probes already run once per protected chunk; repeated VM tick checks are deliberately not cached, preserving later tamper visibility. No additional cache with stale-security risk was added.
- **Transient cleanup:** Prior V1.0.1 cleanup of the pool, decoder factory and plaintext source references remains. No forced GC or default coroutine wrapper is introduced because neither provides dump-proof protection.
- **Version:** V1.0.2 in CLI, web UI, source banner, and anime header. VM9, SEAL4/SEAL2, .lua/.luau/.txt upload, drag-drop and single-line executable body retained.

## Performance comparison

Same 1,000-line `examples/bench_1000.lua`, strong/compact Sealed, seed 1789, Lua 5.4 in this container, 3 separate local runs per version:

| Metric | V1.0.1 | V1.0.2 |
|---|---:|---:|
| Output size | 379,607 bytes | 379,567 bytes |
| End-to-end execution median (three wall-time runs) | 1,123.4 ms | 1,019.1 ms |

Observed improvement: **~9.3%** in this small run set. This is **not** an independent benchmark of Clair and should not be generalized to every script. Both figures include Lua VM execution and process startup, not just the decoder.

## Security boundary

Byte shuffling, lookup tables and unkeyed Adler/xxHash/LCG checks are not authenticated encryption. Host-side tracing and memory capture remain possible. Tests do not demonstrate any 9.5/10 score or superiority over another product.
